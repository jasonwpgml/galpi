# Phase 2 — multi-file 변경 시나리오 설계

작성일: 2026-07-19. 로드맵 Phase 2 항목 "(실험 설계) 3개 파일 이상을 고치는 multi-file
변경 시나리오 포함"의 설계 문서. 구조 인덱스의 정확도 이득은 multi-file 변경에서
최대라는 외부 실증(`docs/plans/external-review-2026-07.md`)을 반영한다.

## 왜 지금 fixture로는 안 되는가

현행 5개 시나리오는 모두 단일 도메인·1~2개 파일 변경이다. Phase 1/1.5의 실측에서
갈피의 이득(관련 없는 읽기 감소, DEAD 회피)은 확인됐지만, 인덱스의 핵심 가설 —
**변경의 파급 범위를 정확히 알려줘서 다중 파일 수정을 빠뜨리지 않게 한다** — 은
검증된 적이 없다. galpi-lab은 도메인이 작아 3+파일 변경이 자연스럽지 않다.

## 시나리오 후보 (Phase 3.5 messy fixture 재측정에 포함)

| ID | 변경 | 파급 파일 수 | 갈피가 도와야 하는 것 |
|---|---|---:|---|
| MF1 | 공용 타입 확장: `Student`에 필드 추가 + 생성·수정·목록·테스트 반영 | 4~5 | `v/y/` symbol view와 `x=` 역의존으로 영향 경로 열거 |
| MF2 | 교차 도메인 규칙: 수강 취소 시 청구 조정 (lesson→billing 신규 연결) | 3~4 | route 2개 도메인 연결, index 경유 강제 |
| MF3 | 계약 변경: `login` 반환 형태 변경 + 세션·테스트·소비자 갱신 | 4+ | `P`(test) 관계로 깨질 테스트 사전 열거 |
| MF4 | 이름 변경 리팩터: 공개 심볼 rename (semantic-safe) | 3+ | Y 레코드로 사용처 열거; doctor/optimize 규칙 검증과 연결 |

## 측정 추가 항목 (기존 Phase 1 지표에 더해)

- **완전성**: 파급 파일 중 실제 수정된 비율 (빠뜨린 파일 수 — 이 시나리오의 핵심 지표).
- **선회 횟수**: 테스트 실패 후 되돌아가 고친 횟수 (인덱스가 파급을 미리 알려주면 감소해야 함).
- 숨은 평가자는 파급 전체를 커버하는 테스트로 작성 (부분 수정은 FAIL).

## 판정 기준

- C(갈피)가 A/B보다 **완전성에서 우위**여야 인덱스 가설이 실증된다.
  토큰 동률이어도 완전성 우위면 multi-file 영역에서는 갈피 채택 근거가 된다.
- A가 완전성까지 동률이면, 해당 규모에서 인덱스는 불필요 (규모 적응형 L0~L1 근거 강화).

## 실행 계획

Phase 3.5의 `galpi-messy-lab` 제작 시 M0~M3 조건에 MF1~MF4 중 최소 2개를 포함한다.
단독 재측정은 하지 않는다 — messy fixture 측정과 합쳐 실행 횟수를 아낀다
(같은 45~60회 배치에서 단일·다중 파일 시나리오를 함께 측정).
